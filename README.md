## Grocery Product Management System 

หลักการทำงานของระบบ (System Operation)
ระบบนี้ถูกออกแบบโดยใช้แนวคิด Hierarchy (ลำดับชั้น) เพื่อให้โค้ดสามารถนำกลับมาใช้ใหม่ได้ง่าย (Reusability) และมีความปลอดภัยของข้อมูล (Security) โดยแบ่งการทำงานออกเป็น 4 ส่วนหลัก:

# 1. การออกแบบโครงสร้างคลาส (Class Architecture)
ระบบใช้ความสัมพันธ์แบบ "Is-A" Relationship ผ่านการสืบทอด (Inheritance):

Product (Class แม่): ทำหน้าที่เป็นพิมพ์เขียวพื้นฐานของสินค้าทุกชนิดในร้าน (ชื่อ, ราคา, สต็อก)

DiscountProduct (Class ลูก): เป็นสินค้าประเภทพิเศษที่ "เป็น" สินค้าเหมือนกัน แต่มีความสามารถในการจัดการ "ส่วนลด" เพิ่มขึ้นมา

# 2. การควบคุมและปกป้องข้อมูล (Data Encapsulation)
ระบบไม่ได้เปิดให้แก้ไขตัวแปรตรงๆ แต่ใช้การสื่อสารผ่านช่องทางที่กำหนด:

Private Fields (_): ข้อมูลอย่าง _price ถูกล็อกไว้ภายใน Class เพื่อป้องกันไม่ให้โค้ดส่วนอื่นเผลอไปแก้ไขจนข้อมูลเพี้ยน

Setters (เครื่องกรองข้อมูล): เมื่อมีการสั่งแก้ไขราคา ระบบจะรัน Logic ตรวจสอบก่อน (เช่น if (value > 0)) ถ้าข้อมูลผิดพลาด ระบบจะปฏิเสธการแก้ไขทันที

Getters (ช่องทางอ่านข้อมูล): ใช้สำหรับดึงค่าออกไปแสดงผล โดยที่เราสามารถดัดแปลงค่าก่อนส่งออกไปได้ (เช่น การคำนวณราคาสุทธิ)

# 3. ลำดับการทำงานของโปรแกรม (Execution Flow)
เมื่อคุณกดปุ่ม Run ใน DartPad โปรแกรมจะมีลำดับขั้นตอนดังนี้:

Initialization: โปรแกรมเริ่มทำงานที่ฟังก์ชัน main() และทำการสร้างวัตถุ (Object) จาก Class ที่เราเขียนไว้

Constructor Mapping: * เมื่อสร้าง DiscountProduct ตัวโปรแกรมจะเรียก super() เพื่อส่งข้อมูล ชื่อ และ ราคา กลับไปให้ Class แม่ (Product) จัดการเก็บค่าให้

Data Processing: * หากมีการเรียกใช้ Setter ระบบจะเช็คเงื่อนไขความถูกต้อง

หากมีการเรียกใช้ Getter (เช่น finalPrice) ระบบจะคำนวณราคาลบส่วนลดในจังหวะนั้นทันที

Polymorphic Display: เมื่อสั่ง displayInfo() ระบบจะเลือกใช้เมธอดที่เหมาะสมที่สุด (ถ้าเป็นสินค้าลดราคา จะใช้เมธอดที่ถูก @override ไว้เพื่อให้แสดงรายละเอียดส่วนลดด้วย)

# 4. สรุปประโยชน์ของโครงสร้างนี้
Maintenance: ถ้าวันหน้าคุณอยากเปลี่ยนเงื่อนไขการตั้งราคา คุณแก้ที่จุดเดียวใน Setter ของ Class แม่ มันจะมีผลกับสินค้าทุกชิ้นในระบบทันที

Scalability: หากร้านมี "สินค้าสด (PerishableProduct)" ที่ต้องมีวันหมดอายุ คุณก็แค่สร้าง Class ใหม่มา extends Product โดยไม่ต้องเขียนระบบชื่อและราคาใหม่ให้เหนื่อย
